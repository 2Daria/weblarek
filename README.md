# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

# Данные

### Вид оплаты `TPayment`

```ts
type TPayment = 'card' | 'cash' | '';
```

Способ оплаты: `'card'` — онлайн, `'cash'` — при получении, `''` — не выбран (значение по умолчанию).


В приложении используются две сущности — товар и покупатель.

### `IProduct`

Описывает товар.
```ts
interface IProduct {
  id: string;
  description: string;
  image: string;
  title: string;
  category: string;
  price: number | null;
}
```

`price === null` означает «бесценно» — товар нельзя купить.

### `IBuyer`

Данные покупателя, указываемые при оформлении заказа.
```ts
interface IBuyer {
  payment: TPayment;
  email: string;
  phone: string;
  address: string;
}
```

### `TPayment`

```ts
type TPayment = 'card' | 'cash' | '';
```

`''` — значение «не выбран» (валидное состояние модели до выбора пользователем).

### `TBuyerErrors`

Объект ошибок валидации модели покупателя. Ключи соответствуют полям `IBuyer`. Если поле валидно — ключ отсутствует.

### `IProductListResponse`

Объект, возвращаемый сервером для `GET /product/`.

### `IOrderRequest`

Объект, отправляемый на сервер для `POST /order/`. Расширяет данные покупателя суммой заказа и списком id товаров.

### `IOrderResponse`

Ответ сервера после успешного оформления заказа.

# Модели данных

Каждая модель — самостоятельный класс, отвечающий за хранение и изменение конкретного набора данных. Модели **не зависят** ни от слоя представления, ни от коммуникационного слоя.

## Класс `Catalog`

Назначение: хранение каталога товаров магазина и выбранного для подробного просмотра товара.

**Поля:**
- `items: IProduct[]` *(protected)* — массив всех товаров каталога.
- `selected: IProduct | null` *(protected)* — товар, выбранный для подробного просмотра.

**Методы:**
- `setItems(items: IProduct[]): void` — сохраняет переданный массив товаров.
- `getItems(): IProduct[]` — возвращает массив товаров каталога.
- `getItemById(id: string): IProduct | undefined` — возвращает товар по id.
- `setSelectedItem(item: IProduct): void` — сохраняет выбранный товар.
- `getSelectedItem(): IProduct | null` — возвращает выбранный товар.

## Класс `Basket`

Назначение: хранение товаров, выбранных покупателем для покупки, и операции над корзиной.

**Поля:**
- `items: IProduct[]` *(protected)* — массив товаров в корзине.

**Методы:**
- `getItems(): IProduct[]` — возвращает товары корзины.
- `addItem(item: IProduct): void` — добавляет товар (с защитой от дублей).
- `removeItem(item: IProduct): void` — удаляет товар.
- `clear(): void` — полностью очищает корзину.
- `getTotalPrice(): number` — возвращает суммарную стоимость.
- `getCount(): number` — возвращает количество товаров.
- `hasItem(id: string): boolean` — проверяет наличие товара по id.

## Класс `Buyer`

Назначение: хранение данных покупателя и их валидация.

**Поля:**
- `payment: TPayment` *(protected)* — способ оплаты.
- `address: string` *(protected)* — адрес доставки.
- `email: string` *(protected)* — email.
- `phone: string` *(protected)* — телефон.

**Методы:**
- `setData(data: Partial<IBuyer>): void` — точечно сохраняет переданные поля, не затирая остальные. Например, `setData({ address: '...' })` обновит только адрес.
- `getData(): IBuyer` — возвращает копию всех данных покупателя.
- `clear(): void` — сбрасывает все поля в пустые значения.
- `validate(): TBuyerErrors` — возвращает объект ошибок. Если объект пустой — все данные валидны.

Правила валидации:
- все поля должны быть непустыми;
- `payment` должен быть `'card'` или `'cash'` (не `''`).

# Слой коммуникации

## Класс `WebLarekApi`

**Назначение:** получение товаров с сервера и отправка заказа.

Использует **композицию**: в конструктор передаётся объект, соответствующий `IApi`, и его методы `get`/`post` используются для запросов.

**Конструктор:** `constructor(api: IApi)`.

**Поля:**
- `api: IApi` *(protected)* — клиент для запросов.

**Методы:**
- `getProducts(): Promise<IProductListResponse>` — GET `/product/`, возвращает объект с массивом товаров.
- `orderProducts(order: IOrderRequest): Promise<IOrderResponse>` — POST `/order/`, возвращает подтверждение заказа.

# Слой представления (View)

Все компоненты наследуют `Component<T>`. DOM-элементы находятся и кэшируются в полях в конструкторе. Слушатели устанавливаются один раз в конструкторе. Компоненты не хранят данные и не содержат логики — о действиях пользователя они уведомляют через брокер событий или через обработчик, переданный в конструктор (который, в свою очередь, генерирует событие).

## Класс `Card<T>` (базовая карточка)

Родитель для всех карточек. Содержит общий функционал: вывод названия, категории (с подсветкой через `categoryMap`) и цены (с выводом «Бесценно» при отсутствии цены).

**Конструктор:** `constructor(container: HTMLElement)`.

**Сеттеры:** `title`, `category`, `price`.

## Класс `CardCatalog extends Card` (карточка каталога)

Добавляет изображение. По клику на карточку вызывает обработчик из конструктора.

**Конструктор:** `constructor(container: HTMLElement, actions: ICardActions)`.

**Сеттеры:** `image`.

## Класс `CardPreview extends Card` (карточка просмотра)

Добавляет изображение, описание и кнопку действия. Текст кнопки зависит от наличия товара в корзине. При отсутствии цены кнопка блокируется с текстом «Недоступно». По клику на кнопку вызывает обработчик из конструктора.

**Конструктор:** `constructor(container: HTMLElement, actions: ICardActions)`.

**Сеттеры:** `image`, `description`, `price` (переопределён), `inBasket`.

## Класс `CardBasket extends Card` (строка корзины)

Добавляет порядковый номер и кнопку удаления. По клику на кнопку удаления вызывает обработчик из конструктора.

**Конструктор:** `constructor(container: HTMLElement, actions: ICardActions)`.

**Сеттеры:** `index`.

## Класс `Page` (главная страница)

Выводит каталог и счётчик корзины. Уведомляет о клике по иконке корзины.

**Конструктор:** `constructor(container: HTMLElement, events: IEvents)`.

**Сеттеры:** `counter`, `catalog`.

## Класс `Modal` (модальное окно)

Самостоятельный компонент без наследников. Выводит любое переданное содержимое. Открывается и закрывается через модификатор `modal_active`. Закрывается по клику на крестик и по клику вне контента.

**Конструктор:** `constructor(container: HTMLElement, events: IEvents)`.

**Сеттеры:** `content`.

**Методы:** `open()`, `close()`.

## Класс `BasketView` (содержимое корзины)

Выводит список товаров (или «Корзина пуста»), итоговую сумму, управляет активностью кнопки оформления. Уведомляет о нажатии кнопки оформления.

**Конструктор:** `constructor(container: HTMLElement, events: IEvents)`.

**Сеттеры:** `items`, `total`, `isEmpty`.

## Класс `Form<T>` (базовая форма)

Родитель для форм. Отслеживает ввод (генерирует событие изменения поля) и отправку (генерирует событие сабмита). Управляет активностью кнопки и выводом ошибок.

**Конструктор:** `constructor(container: HTMLFormElement, events: IEvents)`.

**Сеттеры:** `valid`, `errors`.

## Класс `OrderForm extends Form` (форма оплаты и адреса)

Способ оплаты выбирается двумя кнопками (выбранная подсвечивается модификатором `button_alt-active`). Уведомляет о выборе оплаты и изменении адреса.

**Конструктор:** `constructor(container: HTMLFormElement, events: IEvents)`.

**Сеттеры:** `payment`, `address`.

## Класс `ContactsForm extends Form` (форма контактов)

Поля email и телефон.

**Конструктор:** `constructor(container: HTMLFormElement, events: IEvents)`.

**Сеттеры:** `email`, `phone`.

## Класс `Success` (окно успеха)

Выводит списанную сумму. Уведомляет о нажатии кнопки «За новыми покупками!».

**Конструктор:** `constructor(container: HTMLElement, actions: ISuccessActions)`.

**Сеттеры:** `total`.

# События

В приложении используется событийное взаимодействие через `EventEmitter`. Модели генерируют события при изменении данных, представления — при действиях пользователя. Все события обрабатываются в презентере.

## События моделей данных

| Событие | Когда генерируется |
|---|---|
| `catalog:changed` | Изменился массив товаров в каталоге (`Products.setItems`) |
| `preview:changed` | Изменился выбранный для просмотра товар (`Products.setSelectedItem`) |
| `basket:changed` | Изменилось содержимое корзины (`Basket.addItem` / `removeItem` / `clear`) |
| `buyer:changed` | Изменились данные покупателя (`Buyer.setData` / `clear`) |

## События представлений

| Событие | Данные | Когда генерируется |
|---|---|---|
| `card:select` | `{ id }` | Клик по карточке в каталоге (`CardCatalog`) |
| `preview:toggle` | — | Клик по кнопке покупки/удаления в превью (`CardPreview`) |
| `basket:remove` | `{ id }` | Клик по кнопке удаления в строке корзины (`CardBasket`) |
| `basket:open` | — | Клик по иконке корзины (`Page`) |
| `order:open` | — | Клик по кнопке «Оформить» (`BasketView`) |
| `order:submit` | — | Отправка формы заказа — переход ко второй форме (`OrderForm`) |
| `contacts:submit` | — | Отправка формы контактов — завершение заказа (`ContactsForm`) |
| `order.payment:change` | `{ field, value }` | Выбор способа оплаты (`OrderForm`) |
| `order.address:change` | `{ field, value }` | Изменение адреса (`Form`) |
| `contacts.email:change` | `{ field, value }` | Изменение email (`Form`) |
| `contacts.phone:change` | `{ field, value }` | Изменение телефона (`Form`) |
| `success:close` | — | Клик по кнопке «За новыми покупками!» (`Success`) |

# Презентер

Презентер реализован в основном скрипте приложения `main.ts` (отдельный класс не выделялся, так как у приложения одна страница). Презентер только обрабатывает события — он не генерирует их сам.

В презентере:
1. Создаются экземпляры брокера событий, моделей, слоя коммуникации и компонентов представления. Все компоненты создаются один раз при загрузке страницы.
2. Устанавливаются обработчики всех событий моделей и представлений.
3. Выполняется запрос каталога с сервера и сохранение товаров в модель.

## Обработчики событий в презентере

| Событие | Что делает обработчик |
|---|---|
| `catalog:changed` | Создаёт карточки каталога из товаров модели и выводит их на главную страницу |
| `card:select` | Находит товар по id в модели каталога и сохраняет его как выбранный |
| `preview:changed` | Берёт выбранный товар из модели и выводит его превью в модальном окне |
| `preview:toggle` | Берёт выбранный товар; добавляет его в корзину или удаляет, затем закрывает окно |
| `basket:remove` | Находит товар по id и удаляет его из корзины |
| `basket:changed` | Обновляет счётчик в шапке и перерисовывает содержимое корзины |
| `basket:open` | Выводит корзину в модальном окне |
| `order:open` | Выводит форму заказа (первый шаг) в модальном окне |
| `order:submit` | Выводит форму контактов (второй шаг) в модальном окне |
| `order.*:change`, `contacts.*:change` | Сохраняет изменённое поле в модель покупателя |
| `buyer:changed` | Обновляет состояние форм (валидность и текст ошибок) |
| `contacts:submit` | Отправляет заказ на сервер, показывает окно успеха, очищает корзину и данные покупателя |
| `success:close` | Закрывает модальное окно |

Представление перерисовывается только при обработке события от модели (данные изменились) или при открытии модального окна. После сохранения данных в модель презентер не вызывает перерисовку напрямую — она происходит как реакция на событие модели.
